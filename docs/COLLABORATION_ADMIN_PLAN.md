# Plan hoàn thiện comment, notification và quản trị

Agent chính tự kiểm tra/triển khai theo quyền đã giao, không dùng sub-agent.

1. Thêm issue_comments.version (backfill 0, NOT NULL) và updated_at bằng migration 006. CommentResponse trả version/updatedAt và userId nullable cho dữ liệu legacy không còn tác giả. CreateCommentRequest giới hạn text 1..10000 ký tự, kiểm ở HTTP và service. AddComment giữ transaction, thêm khóa project/refresh issue trước ghi để không xen với xóa issue, audit cùng notification; lỗi rollback. Lỗi ID/quyền chuẩn hóa 404/403.
2. PUT /api/issues/{issueId}/comments/{commentId} nhận commentText và expectedVersion; DELETE cùng route nhận expectedVersion query. Tra issue, VIEW_PROJECT, tra comment và xác minh comment.issue_id đúng URL (sai 404). Chỉ tác giả hoặc EDIT_ISSUE của project được sửa/xóa; tác giả đã rời project cũng cần VIEW_PROJECT. Thiếu quyền 403 trước ghi.
3. Khóa project, refresh comment, so version (cũ 409), rồi cập nhật text/updated_at hoặc xóa comment và audit COMMENT đúng ID. Flush trước mapper để version mới đúng DB. Không gửi lại notification “bình luận mới” khi chỉ sửa/xóa. Entity bị xóa trong lúc chờ refresh trả 404, không tạo lại bản ghi.
4. NotificationInboxService dùng userId từ danh tính, không nhận recipient ID từ request. GET /api/notifications/unread-count đếm chưa đọc; PUT /api/notifications/read-all bulk update WHERE user_id=current AND read=false, trả số đã đổi, gọi lại trả 0. DELETE /api/notifications/{id} chỉ owner, 404 thiếu ID, 403 khác người nhận; không xóa issue/user. MarkAsRead cũ cũng trả lỗi typed 403/404.
5. GET /api/admin/audit-logs chỉ SYSTEM_ADMIN, phân trang page>=0,size1..100, sort created_at DESC/audit_id DESC. Filter entityType/entityId, actorId, action, createdFrom/To; ID dương, entityId cần entityType, from<=to; sai 400 trước query. Specification tại DB, LEFT FETCH actor trong query dữ liệu, không fetch count. Trả DTO gồm ID, actor nullable, action/entityType/entityId/description/thời điểm và thông tin trang, không trả entity/password.
6. GET /api/admin/overview cần SYSTEM_ADMIN, trả count user/enabled user/project/issue/ACTIVE/CLOSED sprint bằng truy vấn count; không ghi DB. Audit API đọc mọi loại chỉ dành admin, không expose log project khác cho thành viên thường.
7. Migration 006 thêm index cho thứ tự audit và inbox user/read. Dùng bảng sẵn có, không thêm realtime/WebSocket hay phụ thuộc ngoài trong đợt này. Notification hiện hữu là DB inbox; các API mới hỗ trợ polling/đọc hàng loạt.
8. Unit/HTTP kiểm ownership, version, body/filter/page, admin gate và nullable actor/tác giả. PostgreSQL kiểm edit/delete/version stale, hai edit cùng version chỉ một thành công, comment/audit rollback khi lỗi, comment thêm đồng thời với issue delete dưới khóa chung, inbox owner scope/read-all idempotent, audit filter/count/null actor và overview. Không coi mock service là kiểm DB hoặc E2E.

Text comment cần đổi varchar(255) sang text trong migration 006 để mức 10000 ký tự được lưu thật. Phân trang audit và issue search chặn offset vượt Integer.MAX_VALUE để request page cực lớn trả 400 thay vì lỗi nội bộ.
