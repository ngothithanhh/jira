# Plan tài khoản, người dùng và vai trò thành viên

Agent chính tự kiểm tra/triển khai theo quyền tiếp tục đã giao; không dùng sub-agent.

1. Thêm users.enabled=true và auth_version=0 bằng migration 005 additive. UserPrincipal lấy hai trường từ users, JWT thêm claim ver. Token cũ thiếu ver được coi 0; filter so ver với DB, kiểm enabled trước controller. Tăng auth_version sẽ làm access token cũ không còn hợp lệ; token không chứa role nên thay vai trò vẫn kiểm DB ở mỗi request.
2. PATCH /api/account/profile: ID users lấy từ danh tính hiện tại, không nhận target ID. Khóa user, refresh và kiểm enabled, sửa userName/fullName khác null (độ dài 50/100, tên không blank), trả UserResponse có enabled. Không sửa email/role/mật khẩu ở route này.
3. POST /api/account/password: oldPassword/newPassword từ body. Khóa current user rồi kiểm hash cũ, mật khẩu mới 8..72 byte UTF-8. Sai 400 trước ghi; đúng thì encode hash mới, tăng auth_version và thu hồi toàn bộ refresh của user cùng transaction/audit. Trả 204, người dùng đăng nhập lại; không trả token hoặc hash.
4. Thứ tự khóa thống nhất user trước refresh token. consumeAndRotate tra token không khóa chỉ để lấy users.user_id, khóa/refresh user rồi khóa/refresh token và mới kiểm revoked/hạn/rotation. Tài khoản disabled trả 401, không cấp child; reuse vẫn commit thu hồi family trước lỗi. Logout gọi revokeSession theo cùng thứ tự, thu hồi family kể cả token cũ đã revoked, idempotent với token có tồn tại.
5. Login có transaction: tra user theo email, khóa/refresh user trước AuthenticationManager để đổi mật khẩu không xen giữa kiểm hash và mint token. Mint JWT theo auth_version vừa khóa và lưu refresh cùng transaction. Register cũng transaction; giữ unique email ở DB, JWT version mặc định 0 cho user mới. Legacy helper verify/rotate/revoke được giữ tương thích nhưng AuthService không dùng chúng để xử lý refresh/logout công khai.
6. Admin GET /api/admin/users/{userId}/roles, PUT/DELETE /api/admin/users/{userId}/roles/{roleId} và PATCH /api/admin/users/{userId}/enabled cần SYSTEM_ADMIN toàn cục. roleId là user_roles; lưu user_role_assignments, khác project_members. Lock các dòng role SYSTEM_ADMIN (upper, theo ID) làm khóa chung cho thay quản trị; sau đó khóa/refresh actor và target, recheck quyền/enabled của actor sau khi chờ.
7. Trước thu hồi admin hoặc disable admin đang enabled, đếm assignment admin của user enabled; còn một thì 409, không ghi. Các mutation admin cùng chờ role lock nên hai lượt không cùng bỏ hai admin cuối. Đổi enabled tăng auth_version/thu hồi refresh; gán/gỡ role idempotent theo khóa ghép. Không thay password bằng API quản trị này.
8. Giữ role SYSTEM_ADMIN làm cấu hình dành riêng: API role không tạo tên đó, không đổi tên role khác thành SYSTEM_ADMIN, không đổi/xóa role SYSTEM_ADMIN đang dùng làm khóa quản trị. Seeder vẫn tạo trực tiếp như hiện tại. Endpoint xóa user hiện có giữ DELETE_USER gate rồi chuyển vào luồng admin có khóa; user còn global role phải gỡ trước (last admin không gỡ được), FK dữ liệu đang dùng trả 409. Disable là lựa chọn giữ lịch sử.
9. PUT /api/projects/{projectId}/members/{userId}/role nhận roleId. Cần ADD_MEMBER của đúng project, khóa project rồi tra member/role, không cho SYSTEM_ADMIN làm role project mới; PM mới chỉ được nhận nếu không có PM khác. Chỉ đổi project_members.role_id, giữ assigned_at và không cấp role toàn cục. Audit cùng transaction.
10. Add/remove member hiện có bổ sung transaction/khóa project dùng chung để hai lượt thêm/đổi PM không vượt giới hạn. Add role SYSTEM_ADMIN bị từ chối; remove lead trả 409 vì lead vẫn có quyền từ projects.lead_user_id. Không xóa user/issue khi gỡ thành viên. DTO/mapper không trả hash, auth_version hay refresh token.
11. Unit/HTTP kiểm profile/password/body, version JWT/disabled, quyền admin/last admin, member role/PM; PostgreSQL kiểm hash và thu hồi phiên thật, hai admin cuối chạy đồng thời, refresh chạy với đổi mật khẩu/disable, rollback audit và migration lặp. JWT filter test dùng khóa test và UserPrincipal thật. Không kết luận đã kiểm SMTP/FE; phạm vi đợt này là profile, đổi mật khẩu đã đăng nhập, trạng thái tài khoản và gán role.

GlobalSecurity đọc tên role từ quan hệ lazy trong transaction read-only, để các kiểm tra quyền không phụ thuộc Open EntityManager In View. Integration account dùng DaoAuthenticationProvider và CustomUserDetailsService thật để kiểm login; quyền project vẫn mock theo bộ integration hiện có.
