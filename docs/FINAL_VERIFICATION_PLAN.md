# Plan kiểm tra ứng dụng đầy đủ sau các đợt

1. Thêm SystemSmokeIT dùng SpringBootTest trên cổng ngẫu nhiên, bind loopback, schema smoke trong chính cluster/container test đã được xác minh trước DDL. Không dùng DB ứng dụng. Database dynamic gọi cùng preflight với PostgresRegressionIT; JDBC tạo schema riêng trước khi Hibernate chạy. Config của lớp DataJpaTest phải là TestConfiguration để không lọt vào component scan của app thật.
2. Full context dùng SecurityConfig/JWT/UserDetails/AuthenticationManager/GlobalSecurity/ProjectSecurity/controller/service/repository thật. Cloudinary properties là dummy, SMTP trỏ loopback với test-connection=false và không gửi thư; không gọi upload/xóa tệp ngoài. Không sửa credential cục bộ hoặc cấu hình DB người dùng.
3. Tạo user/role/project/type/status/workflow fixture đã commit trong schema test, dùng password test. HTTP login lấy JWT rồi đi qua issue CRUD/backlog, sprint start, board/mapping/move với expectedVersion, report snapshot, comment version, inbox và audit/overview. Kiểm một user thường bị 403 ở admin route và token cũ bị 401 sau đổi mật khẩu; dữ liệu backend/JSON phải khớp, không chỉ HTTP 200.
4. GET /v3/api-docs phải trả 200 và mô tả các route mới/bearerAuth. Nếu runtime phát hiện incompatibility thư viện, đọc phiên bản/code trong môi trường và tài liệu chính thức để chọn bản tương thích, ghi plan/fix và retest. Không nhận MockMvc với service mock là chứng minh Swagger hoặc wiring full app.
5. Chạy scripts/test-postgres.ps1 -WithUnit từ clean để unit/MockMvc, PostgreSQL service integration và HTTP smoke cùng chạy trên DB test. Đọc tổng Surefire/Failsafe; 0 skip mới ghi đủ số case. Dừng cluster sau Maven, giữ log, không đưa cache/secret/jar có cấu hình cục bộ vào commit.
6. Hoàn thiện FEATURE_STATUS.md ánh xạ 19 nhóm UC tới API/test và các giới hạn: checkout chỉ backend, không có FE/E2E; chưa benchmark mọi interleaving/dịch vụ ngoài; migration triển khai là script cần áp dụng trước chạy bản mới. Không báo hết bug hoặc mọi chức năng mở rộng ngoài phạm vi đã chốt.

Phát hiện khi chuẩn bị caller HTTP: IssueTypeResponse chỉ trả typeName nhưng API gán loại vào project cần issueTypeId. Bổ sung trường issueTypeId và map ID DB (không đổi trường cũ) để client lấy ID ngay từ POST/GET thay vì buộc tra DB. Smoke phải lấy ID từ JSON thật và dùng cho bước gán/create; unit mapper xác nhận ID không bị mất.

Smoke tái hiện /v3/api-docs ném NoSuchMethodError ControllerAdviceBean với springdoc 2.5.0/Spring 6.2, lỗi dispatch bị security /error biểu hiện thành 401. Nâng springdoc lên 2.10.0 thuộc dải hỗ trợ Boot 3.5 theo bảng chính thức https://springdoc.org/v2/#_what_is_the_compatibility_matrix_of_springdoc_openapi_with_spring_boot. Không đổi quyền /api/**; retest generation thật, bearerAuth và danh sách route.

AuditLog.description có sửa cục bộ từ trước NVARCHAR(MAX) thành TEXT để chạy PostgreSQL. Giữ đúng sửa này và đưa vào commit cuối vì NVARCHAR(MAX) không phải kiểu PostgreSQL hợp lệ; nếu bỏ ngoài commit thì checkout mới không tạo được bảng audit như môi trường đã test. Không đụng cấu hình cá nhân/secret và docker-compose đang có sẵn.
