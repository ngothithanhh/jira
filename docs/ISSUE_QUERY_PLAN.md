# Plan chi tiết, tìm kiếm và xóa issue

Agent chính tự kiểm tra/triển khai theo quyền tự tiếp tục đã giao, không dùng sub-agent.

1. GET `/api/issues/{issueId}`: ID issues trên URL → tra issue (404) → lấy project sở hữu → VIEW_PROJECT (403) → mapper trong read-only transaction. Trả IssueResponse có version, không ghi DB.
2. GET `/api/projects/{projectId}/issues/search`: projectId là projects, phải tồn tại và có VIEW_PROJECT trước query. Query keyword tìm không phân biệt hoa thường trong key/summary/description, %/_ được escape để coi là chữ. Optional statusId/typeId/assigneeId/reporterId/sprintId là ID bảng tương ứng; sprint phải tồn tại và cùng project, sai project trả 400. unassigned=true lọc assignee null. Nếu gửi unassigned cùng assigneeId trả 400. Priority lọc chính xác không phân biệt hoa thường.
3. Specification luôn AND projectId với các filter, không dùng findAll rồi lọc trên bộ nhớ. Fetch các quan hệ mapper dùng trong query dữ liệu, không fetch trong count. Phân trang page>=0, size 1..100; keyword tối đa 200 ký tự. Sort chỉ cho issueNumber/summary/priority/createdAt/updatedAt, ASC/DESC; thêm issueId để ổn định trang. Request sai trả 400. Trả `{items,page,size,totalItems,totalPages}`, không lộ JPA Page nội bộ.
4. DELETE `/api/issues/{issueId}?expectedVersion=N`: tìm issue, kiểm DELETE_ISSUE trên project, khóa project rồi refresh, so version; cũ trả 409 trước ghi. Có issue con hoặc attachment thì 409, yêu cầu xử lý riêng trước, không tự xóa cây hoặc gọi Cloudinary trong transaction.
5. Khi đủ điều kiện, xóa đúng các bản ghi phụ thuộc issue qua JPQL (Notification, IssueComment, IssueTransition, BoardIssue, SprintIssue, WorkLog, IssueVersion), sau đó xóa issues và flush. Giữ nguyên user/project/status/version định nghĩa. Ghi audit DELETE/ISSUE chứa ID và key trong cùng transaction. Lỗi/FK do lượt ghi không dùng khóa làm rollback cả luồng; trả 409, không tự retry hoặc xóa dữ liệu ngoài scope.
6. Để xóa issue số cao nhất không làm tái dùng mã cũ, thêm projects.issue_sequence (int>=0). createIssue đang giữ khóa project, lấy max(sequence, MAX(issue_number))+1, ghi sequence và issue cùng transaction. Migration 003 thêm cột, backfill từ MAX hiện có và chạy lặp an toàn. Không thể khôi phục số đã xóa trước migration nếu không còn lịch sử; không tự suy đoán audit cũ. Tràn int trả 409 trước ghi.
7. Test quyền, filter AND/project, null relations, wildcard literal, sort/page invalid, sprint khác project, chi tiết, stale delete, child/attachment guard, cleanup đúng một issue, audit rollback và tạo sau xóa không tái dùng số. HTTP kiểm route/body/query; PostgreSQL riêng kiểm SQL phân trang/count/filter, FK cleanup, rollback, migration hai lần và sequence. Chưa kiểm FE hay mọi race giữa delete và các API phụ không lấy khóa project; DB FK bảo vệ tính toàn vẹn, xung đột rollback.
