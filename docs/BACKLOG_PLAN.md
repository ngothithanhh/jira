# Plan product backlog và sprint backlog

Agent chính tự kiểm tra theo quyền triển khai tự động đã giao; không dùng sub-agent.

1. `BacklogController` nhận projectId từ `/api/projects/{projectId}/backlog` hoặc sprintId từ `/api/sprints/{sprintId}/issues`. Đây là ID bảng projects/sprints, không phải boardId. PUT thêm `/order`, body `{"issueIds":[5,9]}` là toàn bộ ID issues theo thứ tự mong muốn. ID null/không dương/trùng trả 400, không ghi DB.
2. `BacklogService` tra project/sprint (thiếu: 404), lấy project sở hữu để xét quyền. GET cần VIEW_PROJECT; PUT project cần EDIT_ISSUE hoặc MANAGE_SPRINT, PUT sprint cần MANAGE_SPRINT. Thiếu quyền: 403 trước khi truy vấn nội dung. PUT khóa projects bằng findByIdForUpdate, sau khóa refresh sprint để không dùng state cũ khi chờ. Sprint CLOSED không sửa, trả 409.
3. Repository product lấy issues đúng project, status khác category DONE (kể cả status null), không có sprint_issues thuộc FUTURE/ACTIVE. Lịch sử CLOSED không cản xuất hiện trong product backlog. Repository sprint lấy mọi issue trong sprint, kiểm project từng issue; liên kết cũ sai project trả 409. Các quan hệ tùy chọn dùng LEFT JOIN FETCH để mapper không bỏ mất issue thiếu assignee/parent/status.
4. Đọc sắp theo rank đã lưu trước; rank null xếp sau theo priority HIGHEST/HIGH/MEDIUM/LOW/LOWEST, còn lại cuối; tie theo issue_number rồi issue_id. Thêm nullable `issues.backlog_position` và `sprint_issues.position` bằng SQL additive chạy lặp được, không sửa/xóa dữ liệu cũ, không unique rank để tránh lỗi đổi chỗ khi flush.
5. PUT đọc lại danh sách hợp lệ dưới khóa. `validateOrder` so set của request bằng toàn bộ set hiện tại; thiếu/thừa/sai project/sai scope trả 409 trước cập nhật. Hợp lệ mới gán rank 0..N-1 và ghi cùng transaction. Lỗi giữa các bước rollback toàn bộ. Response dùng IssueResponse hiện tại và thứ tự list, không đổi hợp đồng API issue cũ.
6. Khi thêm/gỡ/chuyển sprint, reset backlog_position của issue để việc trở về backlog xếp sau các vị trí đã chốt; link mới có position null. Dùng khóa project chung đã có ở add/remove/start/complete. Bổ sung khóa project rồi refresh issue cho update/assign/status để status DONE không đổi giữa kiểm scope và ghi reorder. Khóa theo thứ tự project trước, không khóa issue trước project. Không gọi dịch vụ ngoài, không thêm retry hay tự ghi đè khi nhận 409.
7. Test quyền, null/duplicate/body, scope khác project, DONE tên tùy chỉnh, lịch sử CLOSED, đọc lại rank, reorder lỗi không ghi, sprint CLOSED và race thêm issue/trạng thái trong lúc reorder. PostgreSQL riêng kiểm JPQL/DDL/migration chạy lặp và kết quả commit; MockMvc kiểm route/validation, không coi mock là kiểm DB.
